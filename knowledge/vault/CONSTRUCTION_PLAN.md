# Construction strategy

1. Establish navigable local construction knowledge and pinned requirements (this bootstrap).
2. In parallel where scope permits: derive reviewed schema/authorization/source-to-target contracts from v1.0; inspect the starters the user creates and record exact repository/deployment/project bindings.
3. Review and selectively clean each actual starter on an isolated branch. Preserve existing code/data/history; do not delete projects or schemas blindly. Standardize verified commands, dependency locks, migrations and deployment directories.
4. Build one complete real-database business path per department plus exact Owner counterpart, using authenticated identities, constraints/RLS, actual evidence and transaction/idempotency boundaries. Unit/domain checks alone do not prove browser/API/database authorization.
5. Add reproducible ETL and local dimensional marts from verified operational records, then approved export -> Owner intake/reconciliation -> warehouse/marts/reports. No direct dashboard reads of private foreign OLTP or guessed metrics.
6. Expand through prerequisite-ready workflows. Record exact evidence before unlocking dependent tasks. Keep historical prototype findings as reference, not a shortcut around source/schema/security verification.

Small complete vertical increments are preferred to giant skeletons, repeated plans or rare-exception expansion. A starter migration can be reviewed offline; applying it requires actual verified project access and a reversible migration strategy. Do not make all knowledge dependent on a blocked deployment.
